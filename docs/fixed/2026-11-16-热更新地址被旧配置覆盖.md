# 热更新地址被旧配置覆盖

> 日期：2026-11-16
> 分支：`feat/v6-system`

## 现象

客户 Windows 机器安装 v0.1.1 后，启动日志仍然是旧更新地址：

```text
https://cdn.example.com/xdesin-hmi/latest.json
https://github.com/xdesin/xdesin-hmi/releases/latest/download/latest.json
```

CDN 请求 DNS 解析失败，GitHub 请求返回 Not Found，最终提示「无可用热更新」。
重新安装 v0.1.1 后现象不变。

## 原因

不是 server 热更新包内容不对，也不是安装包没有替换 server 资源。

更新地址的取值链路为：

```text
React loadConfig()
  → invoke('get_app_config')
    → Rust ConfigManager（读取 config.json / AppConfig::default）
      → mergeConfig 使用 Rust 返回的非空旧值
```

Rust 端 `src-tauri/src/config.rs` 的更新源默认值仍是模板占位：

```rust
cdn_url: "https://cdn.example.com/xdesin-hmi"
github_repo: "xdesin/xdesin-hmi"
```

而 `ConfigManager::new` 首次启动会把默认值写入：

```text
%APPDATA%\com.xdesin.hmi\config.json
```

因此即使 Next.js 构建时已经写入七牛 CDN，`get_app_config` 返回的旧 `cdnUrl` / `githubRepo` 仍会覆盖构建时的默认值。已落盘的旧配置也会在升级后继续存在，所以重装后仍然请求旧地址。

## 修复

1. Rust 默认更新源改为正式地址：
   - CDN：`https://o09u11p5v.qnssl.com/hmi`
   - GitHub：`ggtiger/hmi01`
2. `ConfigManager` 加载和保存配置时迁移已知占位值：
   - `https://cdn.example.com` 及其子路径
   - `xdesin/xdesin-hmi`
   - 空字符串
3. 前端 `lib/config.ts` 在 `mergeConfig` / `saveConfig` 时同样忽略占位值，避免旧 Rust 配置继续覆盖构建时默认值。
4. 用户自定义的其他更新地址保持不变。

## 发布注意

该问题包含 Rust 侧默认值和配置迁移，**只发 server 热更新无法修复已安装客户端的配置读取逻辑**，必须发布新的 Windows 全量安装包（v0.1.2）。已安装旧版客户端可先手工修改：

```text
%APPDATA%\com.xdesin.hmi\config.json
```

把 `update.cdnUrl` 改为七牛地址、`update.githubRepo` 改为 `ggtiger/hmi01`，重启后即可接入 server 热更新。
