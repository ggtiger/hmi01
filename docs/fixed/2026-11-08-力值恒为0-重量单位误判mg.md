# 力值恒为 0：设备重量字段单位误判为 mg

> 日期：2026-11-08
> 现象：WEIGHT_SO3 转向力模块已连接，AD 内码正常（如 32909），但界面实时力值恒为 -0.00 N；诊断显示「原始 -1 mg」
> 提交：本次提交

## 一、根因

`scale_protocol.rs` 沿用 SSTS 称重模块协议，把设备回传的重量字段当作 **mg** 换算：

```rust
let weight_g = weight_mg / 1000.0;
let weight_n = weight_mg / 1_000_000.0 * 9.80665;
```

本平台 WEIGHT_SO3 模块回传字段单位实际是 **N**（用户确认）。设备回传 20（N）被当成 20 mg → 0.000196 N，界面显示 0.00。诊断中「原始 -1 mg」实际是 -1 N（空载），因此永远显示 ≈0。

## 二、修复

- 协议层字段重命名 `weight_mg` → `weight_raw`（单位 N），`ScaleData.weight_n` 直接取原始值：
  ```rust
  let weight_n = frame.weight_raw as f64;   // 设备单位即 N
  let weight_g = (weight_n / 9.80665) * 1000.0;
  ```
- 前端 `ForceData.weightMg` → `weightRaw`，诊断显示改为「原始 -1 N」
- 设置页校准按钮按状态智能切换：
  - 原始重量 ≈0（设备未输出重量）→「设备标定」：发送 0xAA 砝码标定命令（方法号 0x09），设备据此开始换算
  - 已有读数 →「系数校准」：按 `标准值 ÷ 当前读数` 计算软件校正系数
- 校准说明更新为四步（清零 / 设备标定 / 系数校准 / 系数）

## 三、验证

- `cargo test` 31/31（新增 `test_weight_unit_is_newton`：回传 20 → 20 N）
- `tsc` 零错误；`next build` 11/11
- 预期：连接后实时力值显示设备真实 N 值；若仍为 0，用「设备标定」放砝码标定后再看

## 四、后续修正（用户反馈按压无响应）

现象：用户按压施加力后 AD 内码变化（32909 → 49749）但重量恒为 -1 N，力值不变；且校准输入单位应为 N 而非砝码克数。

- 按钮逻辑修正：原按钮按「读数≈0」自动切换，-1 N 被误判为"已有读数"，导致**设备标定按钮不可见**。现改为两个按钮常驻：
  - **设备标定**：输入标准载荷（N）→ 换算为克后发送 0xAA 0x09 命令，让设备按载荷换算重量
  - **系数校准**：软件校正系数（标准 N ÷ 当前读数）
- 输入框单位由「砝码 g」改为「标准 N」，设备标定命令仍按协议换算为克发送
- ForceModal 校准区同步（标准 N + 设备标定 / 系数校准两个按钮）

## 五、AD 内码换算方案（设备不输出重量）

用户按压后 AD 内码变化（32909 → 49749）而设备重量恒 -1 N ⇒ 设备固件不输出重量，设备标定命令也不保证生效。改为 **AD 内码标定**：

- `settings-store` 新增 `adCalibration: { zeroAd, nPerAd }`（按通道，localStorage 持久化）
- `channelForceN()`：有 AD 标定时 `(adCode − zeroAd) × nPerAd × 系数`，否则回退设备重量
- 设置页流程：
  1. 空载点「清零」→ 记录 `zeroAd`（同时下发设备零点命令）
  2. 施加已知载荷 N → 填「标准 N」→ 点「校准」→ `nPerAd = N / (adCode − zeroAd)`
  3. 实时力值随 AD 变化
- 转盘页/踏板页/ForceModal 统一经 `channelForceN()` 显示
- 诊断行显示 `AD / ΔAD / N-AD 比例 / 原始 N / 零点`（ΔAD = 当前 AD − 零点 AD，用于判断加力时 AD 是否变化、比例是否合理）
- 校准按钮禁用时在模块行内显示可见原因（未填标准 N / 未清零 / ΔAD 不足等），不再只有按钮灰显无提示
- 未完成 AD 标定（N/AD = 0）时，实时力值显示「未标定」（琥珀色）而非 0，并提示完成校准，避免「AD 变化但实时 0 N」的困惑

## 六、最终结论（数据验证）

后续实测发现设备重量字段实际单位为 **mg**：

- 按压后回传 `981270` → 981.27 g ≈ **9.62 N**（合理）
- 若按 N 解释则是 98 吨（不可能）
- 空载 `-1 mg ≈ 0 N`，此前被误读为"单位为 N 且恒定"

**恢复 SSTS 的 mg 换算**，并调整优先级：

1. 设备重量有效（|weightN| ≥ 0.01）→ **优先**：显示 = weightN × 系数，校准 = 标准 N ÷ 当前读数（SSTS 单按钮）
2. 重量无效 → AD 内码标定兜底
3. 诊断显示「原始 xxx mg」

新增单测 `test_measured_press_weight`（981270 mg ≈ 9.62 N）固化实测向量。

## 七、教训

- 复用其他项目的协议实现时，**单位与字段语义必须对照实际设备确认**——数值恒为 0 的典型原因是数量级换算错误（mg→N 会缩小 10⁶ 倍）
- 诊断显示原始字段（AD + 原始重量）能快速定位：AD 正常而重量恒 0 ⇒ 单位/换算或设备未标定，而非前端系数
