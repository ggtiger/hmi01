# 蓝牙力值模块连接失败后按钮永久禁用（连接挂死）

> 日期：2026-09-20
> 现象：蓝牙模块联结弹窗中点击「连接」后连不上，此后所有连接按钮变灰且不再恢复，无法重试
> 提交：本次提交

## 一、问题复现与定位

复现路径：扫描到设备 → 点「连接到 A」→ 无响应/失败 → 弹窗内全部按钮灰死 → 重启应用才能恢复。

定位：前端 `handleConnect` 的 `finally` 会复位 `busy`，按钮灰死的唯一可能是 **invoke 的 Promise 永远不 resolve**——即 Rust 侧 `force_connect` 挂起。

根因链路：

```
ForceModal.handleConnect() → invoke('force_connect')
  → ForceManager::connect()
    → peripheral.connect()            ← btleplug/CoreBluetooth 在设备
      （设备关机/超范围/被占用时）        不可达时会**无限期挂起**，
      → 永不返回                         无任何超时保护
```

连带问题：连接失败后 btleplug 的 `Peripheral` 实例（按地址缓存在 adapter 中）的 CoreBluetooth 状态未复位，即使前端能重试，后续对该地址的 connect 也可能持续失败。

## 二、修复方案

`src-tauri/src/comm/bluetooth.rs`：

1. **连接全链路超时**：`peripherals()` 5s / `connect()` 15s / `discover_services()` 10s / `subscribe()` 5s（CoreBluetooth 挂起时 tokio timeout 强制返回）
2. **失败清理 `cleanup_failed_connect()`**：任一步失败 → best-effort `peripheral.disconnect()`（3s 超时防再次挂起）→ 复位通道状态 → emit `force-connection-changed` 通知前端 → 返回明确中文错误（如「连接超时（15 秒）——请确认设备已开机、在通信范围内且未被其他程序占用」）
3. Notify 特征缺失时同样清理，并附设备实际特征列表辅助判断「可能不是力值模块」

`components/ui/ForceModal.tsx`：

4. 点击连接时即保存设备地址到 localStorage（原来只在成功后保存）——连接失败后通道卡上也出现「重连」按钮，可直接重试，无需重新扫描

`src-tauri/Info.plist`（新增）：

5. `NSBluetoothAlwaysUsageDescription` 蓝牙权限声明——macOS 打包后（tauri build 自动合并）缺失该 key 时 CoreBluetooth 会静默失败，蓝牙功能不可用

## 三、验证

- `cargo build` 零错误零警告
- 修复后行为：连接失败 → 15s 内返回明确错误 + 弹窗错误条展示 + 通道状态复位（灰灯）→ 「重连」按钮可立即重试
- 硬件连接成功路径待真机复测（需设备可广播）

## 四、教训与关联

- **btleplug 的 `connect()` 没有内置超时**：所有面向用户的 BLE 连接调用必须套 `tokio::time::timeout`，否则设备不可达时 UI 永久挂死
- 失败路径的状态清理与成功路径同等重要：缓存的 Peripheral 实例失败后不复位会"越试越挂"
