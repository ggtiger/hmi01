# 力值校准简化为 SSTS 单按钮流程

> 日期：2026-11-08
> 现象/背景：此前校准 UI 有「设备标定 / 系数校准 / AD 标定」多个按钮与先清零再校准的强条件，用户反馈「参考 SSTS，之前没那么复杂」
> 提交：本次提交

## 一、SSTS 的原始流程（对照）

SSTS `control-force-test/torque-test` 的「力值校正」只有一步：

```ts
const currentForce = scaleState.data?.weightN
const standard = parseFloat(standardValue)
const coefficient = standard / currentForce   // 标准值 ÷ 当前读数
// 保存 correctionCoefficient，显示 = 读数 × 系数
```

即：**施加标准载荷 → 输入标准值(N) → 点「力值校正」**，没有其他按钮。

## 二、简化后的实现

设置页与 ForceModal 统一为：

```
[清零]  [标准 N 输入]  [校准]
```

「校准」内部自动选择换算方式（用户无感知）：

1. **AD 标定**（设备重量字段不可用时）：已记录清零零点且 `|AD − 零点| ≥ 1`
   → `nPerAd = 标准载荷 / (AD − 零点)`，实时力值 = (AD − 零点) × nPerAd
2. **软件系数**（设备读数可用时，SSTS 方式）：`系数 = 标准载荷 / 当前读数`
3. 两者都不满足时按钮可点，行内提示原因（请先清零 / 请先加力 / 填写标准 N）

其他调整：
- 移除独立的「设备标定」「系数校准」按钮（设备标定命令仍保留在 Rust 层/手动调试）
- 清零按钮同时记录 AD 零点（设置页与 ForceModal 一致）
- 未标定时实时值显示「未标定」而不是 0
- 说明文字简化为三步（清零 / 校准 / 系数）
