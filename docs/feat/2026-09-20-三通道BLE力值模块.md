# 三通道 BLE 力值模块（A/B/转向角）

> 日期：2026-09-20
> 现象/背景：踏板/转盘页的力值字段一直显示 `--`。用户澄清：力值不走 WiFi TCP 协议，是平台上三个独立 BLE 力传感器（踏板 A 加载力、踏板 B 加载力、转盘转向力值）——对应设计稿 slide 5「设置模块」的模块 A/模块 B/转向角三通道
> 提交：本次提交

## 一、背景与目标

业务架构：力值采集与运动控制是两条独立链路——运动/遥测走 WiFi TCP（ESP32-S3），力值走 BLE（三个 nRF52 UART 透传模块）。SSTS 已有单设备蓝牙称重模块（btleplug + 0xAA 帧协议），本平台扩展为三通道。

## 二、方案设计

SSTS `ScaleManager`（单设备）→ `ForceManager`（三通道）：
- 共享一个蓝牙适配器，每通道独立 peripheral/特征/连接状态/最新数据/会话最大力值
- 通道标识 `A | B | STEER`，命令统一带 channel 参数
- 事件：`force-data {channel, data}`（100ms 节流）、`force-connection-changed {channel, state}`
- 复用 SSTS 全部成熟模式：锁外异步 BLE 操作、NUS 特征精确匹配→属性回退、探测写入触发 Windows 配对、双重写入策略 + 延迟重试
- 帧协议（scale_protocol.rs）原样复用：0xAA 头 + XOR 校验 + AD 内码/重量 mg/状态/时间戳，mg → g → N（×9.80665）

## 三、实现要点

- `bluetooth.rs`（新，~470 行）：ForceManager 三通道管理；connect 时先断开旧连接；notification_loop 跟踪 maxN
- `force_commands.rs`：force_scan/connect/disconnect/zero/calibrate/reset_max/get_state（7 个，总命令数 33→40）
- 前端 `use-force.ts`：三通道状态订阅（连接/最新力值/最大力值），actions useMemo 稳定
- `ForceModal.tsx`：蓝牙管理弹窗——三通道状态卡（力值实时显示/清零/断开/重连）+ 扫描设备列表（选目标通道连接）+ 砝码标定；上次设备地址 localStorage 记忆
- 踏板测试页：顶部「蓝牙模块联结」按钮（设计稿顶部第一按钮，显示 x/2 连接数）；力值区接当前侧通道（实时/最大/进程力值，进程力值=流程进行中实时跟踪、停止后保持）
- 转盘测试页：力值区接 STEER 通道（STEER_RUN 期间进程力值实时跟踪）
- 设置页：「力值模块（蓝牙）」卡片（slide 5 布局：三通道实时值/系数/清零/砝码校准）
