# Windows 发布与 server 增量/全量更新

> 日期：2026-11-15
> 参考：`/Users/wanghu/work/study/SSTS` 的 release / server-release 工作流

## 一、发布目标

当前只发布 **Windows x64**，通过 GitHub Releases 分发：

- 全量更新：Tauri updater + NSIS 安装包
- server 增量更新：文件级 patch
- server 全量兜底：无匹配 patch 时下载完整 server tar.gz

## 二、新增文件

- `.github/workflows/release.yml`：`v*` tag 触发 Windows 全量发布
- `.github/workflows/server-release.yml`：`server-v*` tag 触发 server-only 发布
- `scripts/configure-release.mjs`：按当前仓库生成 updater 端点和公钥配置
- `scripts/set-release-version.mjs`：同步 package / tauri / Cargo / lock 版本
- `scripts/publish-server-update.mjs`：
  - 打包当前 server
  - 下载最近旧版本 server tar
  - 生成 `__manifest.json` 文件级增量包
  - 更新 `latest.json` 的 `serverVersion` / `serverDeltas` / `serverFullUrl`
  - 上传到 GitHub Release
- `docs/RELEASING-WINDOWS.md`：完整发布步骤和 Secrets 配置

## 三、工作流行为

### 全量 `v*`

```text
tag v0.2.0
  → Windows NSIS 安装包
  → Tauri updater .nsis.zip/.sig + latest.json
  → server-0.2.0.tar.gz
  → server-patch-<old>-0.2.0.tar.gz（最多 3 个旧版本）
  → 更新 latest.json
  → 发布 GitHub Release
```

### 增量 `server-v*`

```text
tag server-v0.2.1
  → 构建 Next standalone server
  → server-0.2.1.tar.gz
  → server-patch-<old>-0.2.1.tar.gz
  → 上传到最近一个 v* Release 并更新其 latest.json
```

不重新构建 Windows 安装包，不改 app version。

## 四、配置要求

- GitHub 仓库需要 `contents: write` 权限（workflow 已声明）
- Secrets：
  - `TAURI_SIGNING_PRIVATE_KEY`
  - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`
  - `TAURI_UPDATER_PUBKEY`
- 当前仓库尚未配置 remote；需要先添加 origin
- 更新端点默认使用 GitHub 公开 Release；私有仓库需要 CDN 或下载鉴权

## 五、更新链路

- `latest.json.version` 变化 → Tauri updater 全量更新
- `latest.json.serverVersion` 变化 → server 热更新
  - 匹配 `serverDeltas.windows-x86_64` → 下载 patch
  - 无匹配/校验失败 → `serverFullUrl` 全量 server 包
- Windows patch 应用由 `delta.rs` 负责：备份 → 应用 → 校验版本/静态资源 → 失败回滚

## 六、验证

- `node --check` 检查发布脚本语法
- 本地构造 old/new server fixture 验证 `__manifest.json` 的 modified/added/deleted 及强制 manifest 逻辑
- `npm run build`、`npx tsc --noEmit` 通过
