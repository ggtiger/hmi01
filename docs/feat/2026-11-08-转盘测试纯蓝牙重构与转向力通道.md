# 转盘测试纯蓝牙重构（新增转向力通道）

> 日期：2026-11-08
> 现象/背景：转盘测试只需蓝牙两台采集设备（倾角模块、转向力模块），无需 WiFi；原页面依赖 TCP 连接/STEER START 命令，力值误取倾角通道（恒为 --），自由转角为方向反转点自动近似而非偏移基准
> 提交：本次提交

## 一、需求与背景

- 字段映射：方向盘 X → 倾角 X，方向盘 Y → 倾角 Y，**合并一行展示**
- 自由转角：数据源倾角 X；清零保存当前倾角 X 为基准，实时值 = 当前 − 基准；顺/逆时针基于自由转角判定
- UI：自由转角清零 / 实时力值清零 / 最大力值记录+清除；移除进程力值与计时控件；趋势清空 = 清空曲线 + 全部历史记录
- 通信：仅依赖蓝牙（倾角模块 + 转向力模块），两模块连上即可开始测试

## 二、实现要点

**新增 TORQUE 转向力通道**（原架构只有 A/B 力值、STEER 倾角、SWITCH 开关）：
- `bluetooth.rs`：`CHANNELS` 5 通道（A/B/STEER/SWITCH/TORQUE）；TORQUE 走既有 0xAA 力值帧解析分支（与 A/B 相同），无需新协议
- `types.ts`：`ForceChannel` 加 `TORQUE`，标签「转向力（转盘力值）」；倾角通道标签改为「倾角模块（转盘 X/Y）」
- `use-force` / `ForceModal` / 设置页：通道枚举与初始化补齐 TORQUE（吸取上次 SWITCH 漏数组的教训，类型 + 枚举同步改）

**页面重构**（`app/steering-test/page.tsx`）：
- 移除全部 TCP 依赖：WiFi 状态框、遥测兜底（`t.steer_x/y`）、`STEER START/STOP` 命令
- 数据源：倾角 = `forceStates.STEER.latestAngle`；力值 = `forceStates.TORQUE.latest.weightN`
- 倾角 X/Y 合并一行（`X / Y` 同一数据块）
- 自由转角 = `tiltX - zeroOffset`，清零按钮保存当前倾角 X；方向标签按符号显示顺时针/逆时针
- 顺/逆时针峰值**默认无值（--），不自动跟踪**：点击该行「记录」时把当前自由转角值写入对应方向（顺时针要求自由转角 > 0，逆时针要求 < 0，不满足则按钮禁用）；「清除」归零；按钮顺序「清除 → 记录」
- 实时力值「清零」= 力值模块零点校准（`force_zero TORQUE`）；最大力值**默认无值（--），不自动跟踪**：点「记录」时把当前实时力值写入峰值行并写入历史记录表，「清除」归零 + `resetMax`
- 自由转角 / 实时力值行同样提供「记录」按钮（清零之后），点记录把当前值写入历史记录表
- 触屏优化：移除页面急停按钮（纯蓝牙场景无 TCP 运动控制）；左侧面板顶部对齐、宽度 540px、行内按钮加大（px-4 / py-2.5 / 14px，最小宽 64px），开始测试与导出按钮加大（py-4 / 16~17px），记录表删除按钮与趋势「清空」按钮扩大触控区
- 开始测试条件 = 倾角 + 转向力两模块均连接（`bleReady`）；未就绪显示琥珀色提示
- 趋势图三条线：倾角 X/Y + 自由转角；右上「清空」同时清空曲线与全部记录点
- 移除进程力值行、底部角度快照记录按钮

## 三、验证

- `cargo test` 30/30；`npx tsc --noEmit` 零错误；`next build` 11/11 页面通过
- 真机：连接倾角（STEER）+ 转向力（TORQUE）两个蓝牙模块 → 两状态框变绿 → 开始测试 → 倾角/自由转角/力值/峰值实时更新

## 四、教训与关联

- 通道枚举有三处（`CHANNELS`/`FORCE_CHANNELS`/`initialStates`），新增通道必须同步，否则 UI 不渲染（上次 SWITCH 就是漏了数组，本次全部补齐）
- 转盘测试与踏板测试的采集链路不同：踏板是 TCP 运动控制 + BLE 力值，转盘是纯 BLE 双模块，页面不应共用 TCP 连接状态
