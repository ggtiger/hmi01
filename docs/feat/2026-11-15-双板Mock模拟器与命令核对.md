## 一、命令核对

按 `plain_test_host.py` 实际下发的命令逐条核对，以下命令均已具备 Rust `Command`、Tauri command、前端 service/action 及 mock 处理：

| Python 工具命令 | Mock 处理 |
|---|---|
| `PING` | `PONG` |
| `DEBUG PLAIN ON/OFF` | 明文切换（含“最后一帧加密 OK”语义） |
| `PEDAL SELECT A/B/NONE` | 维护本板 `pedal_select`，切换时中止流程 |
| `PEDAL A/B START/STOP` | 自动流程、LEVELED/STABLE 事件 |
| `PEDAL A/B LEVEL` | LEVEL START/DONE comp 事件 |
| `PEDAL A/B PUSH START/STOP` | HOMING/STARTED/DONE/STOPPED 事件，自动回零 |
| `PEDAL A/B SET PUSH_DIST <mm>` | 保存推出距离，范围 0–500 |
| `MOTOR PUSH_A/PUSH_B HOME` | 回零并置状态字 Bit1 |
| `MOTOR A/B ZERO` | MSH 软件零点 |
| `SCAN 1 32` | 异步 SCAN 结果行 |
| `SET LEVEL_METHOD` | 保存补正模式 |
| `SET PUSH_PULSES_PER_MM` | 保存脉冲当量 |
| `SET PUSH_FEED` | 保存推杆速度 |

另外补齐了协议中已有、但此前上位机未封装的兼容命令：

- `PEDAL TEST START/STOP`（Rust enum → Tauri command → service → actions，mock 已支持）
- `RESET FAULT`、`GET PARAMS`、`SET LEVEL_SPEED/TOL/RATIO`、`SET MSH_ZERO_CLEAR`、`SET SIDE`、`NET GETCFG/SETCFG/RESET`、`STEER START/STOP` 等。

协议中的 `MOTOR STEER_X/STEER_Y` 虚拟轴未接入当前 UI/Tauri 轴路由（Python 工具未使用；当前方向盘数据走 BLE）。

## 二、Mock 模拟器改造

`scripts/mock-device-server.js` 重写为双板独立模拟：

- 默认同时监听 `A=10001`、`B=10002`；也支持 `MOCK_SIDE`、`MOCK_PORT_A/B` 单板/端口自定义。
- 每块板独立 `DeviceSession`：独立 TCP、nonce、加密/明文状态、心跳、参数、流程状态；互不干扰。
- 遥测按新固件协议只上报本侧字段：`side`、`pedal_x_tilt_*`、`laser_x`、`pedal_x`（mm）、`push_x_raw`、`push_x_st`、`ang_cor_x`，公共 `steer_*`、`sensor`、`state`、`pedal_select`。
- 完整支持参数写入/读取、Modbus 扫描、故障复位、板侧修改、WiFi 配置回显。
- 故障态：`ESTOP` → `state=FAULT` → 运动命令返回 `ERR ... E_FAULT` → `RESET FAULT` → 显式 `MOTOR ENABLE`。
- 手动 `MOTOR MOVE/HOME/STOP` 自动中止本侧自动流程；推杆未回零时 `PUSH START` 先发 `HOMING`。
- 明文切换、加密帧、nonce 回绕/重放保护与 Rust crypto 对拍兼容。

## 三、真实联调方式

```bash
npm run mock:device
# A: 127.0.0.1:10001
# B: 127.0.0.1:10002（App 连接向导里把 B 板端口改为 10002）
```

登录后使用「调试台」可验证全部 TCP 单步命令（不依赖 BLE）；踏板/转盘正式测试仍需要真实 BLE 力值/倾角模块。
